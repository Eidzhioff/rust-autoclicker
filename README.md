# Autoclicker (Rust, Windows)

> ! Проект был написан полностью нейросетью. Исходные, загружаемые для агента, файлы находятся [здесь](https://github.com/Eidzhioff/rust-autoclicker/tree/main/uploads). 

Минималистичный автокликер: **удерживаете выбранную кнопку — приложение кликает ЛКМ**
с заданной задержкой. GUI на `egui/eframe`, работа в фоне через иконку в системном трее.
Замена Python-прототипа по ТЗ (`Task.md`), один автономный `.exe`.

## Возможности

- **Любая кнопка активации**: клавиатура (F1–F24, буквы, цифры, модификаторы, навигация…)
  и мышь (ЛКМ, ПКМ, СКМ, XButton1, XButton2). Кнопка «Слушать» перехватывает следующее
  нажатие (двухфазно: сначала ждёт отпускания всех кнопок, чтобы не поймать клик по
  самому GUI). Esc или «Отмена» — выход из режима, таймаут 10 с.
- **Задержка**: 1–10000 мс, по умолчанию **40 мс** (~25 кликов/с). DragValue + слайдер,
  применяется на лету, без перезапуска.
- **Старт/Стоп** в GUI; статус и ошибки видны в статус-баре.
- **Трей**: крестик окна сворачивает в трей (процесс живёт), ЛКМ по иконке или
  «Показать окно» — разворачивает, «Выход» — полностью завершает приложение.
- **F12 — экстренный выход**: отдельный поток завершает процесс, даже если GUI завис.
- Иконка вшита в `.exe` (трей, окно, Проводник) — внешних файлов не нужно.
- Точность задержки: `timeBeginPeriod(1)` даёт реальную гранулярность ~1 мс
  (без него Windows округляет `sleep` до ~15.6 мс).

## Сборка

Нужен Rust (stable, tested on 1.100):

```sh
cargo build --release
# → target/release/autoclicker.exe  (один файл, без консоли)
```

Кросс-сборка из Linux (MinGW):

```sh
rustup target add x86_64-pc-windows-gnu
# Debian/Ubuntu: apt install gcc-mingw-w64-x86-64
cargo build --release --target x86_64-pc-windows-gnu
# → target/x86_64-pc-windows-gnu/release/autoclicker.exe
```

Release-профиль: `lto = "thin"`, `codegen-units = 1`, `strip = true`, `panic = "abort"`;
консоль скрыта атрибутом `windows_subsystem = "windows"` (в debug-сборке консоль есть).

Юнит-тесты логики (клавиши, настройки, машина состояний «Слушать») кроссплатформенные:

```sh
cargo test          # работает и на Linux/macOS (WinAPI заменён заглушками)
cargo clippy --target x86_64-pc-windows-gnu -- -D warnings
```

## Использование

1. Запустите `autoclicker.exe`. По умолчанию: кнопка **XButton2** («Вперёд»), задержка **40 мс**, остановлен.
2. При необходимости нажмите «Слушать» и нажмите нужную клавишу/кнопку мыши.
3. Нажмите **Старт**. Удерживайте кнопку активации — идут клики ЛКМ; отпустите — клики прекращаются.
4. Крестик — свернуть в трей (кликер продолжает работать). ЛКМ по иконке трея — вернуть окно.
5. «Выход» в меню трея — корректное завершение. **F12** — аварийное завершение из любого состояния.

Логи: `RUST_LOG=info` (в release уровень по умолчанию `warn`; в debug-сборке видно в консоли).

## Архитектура

| Поток | Что делает |
|---|---|
| main | message pump (winit/eframe) + трей; `App::logic()` опрашивает каналы даже при скрытом окне (~100 мс) |
| clicker | опрос `GetAsyncKeyState(vk) & 0x8000`, клик `SendInput` (down+up), динамическая задержка; режим «Слушать» |
| emergency | опрос F12 каждые 30 мс → `process::exit(0)` мимо GUI |

Связь: `Arc<Mutex<Settings>>` (GUI пишет, кликер читает снимки), `mpsc`-канал событий в GUI,
`AtomicBool`-флаг остановки. Весь `unsafe` изолирован в `src/winapi.rs`.

```
src/main.rs     — точка входа, сборка потоков/трея/GUI, graceful shutdown
src/app.rs      — GUI (egui): контролы, статус, перехват крестика, события трея
src/clicker.rs  — поток кликера, захват кнопки, аварийный watcher
src/settings.rs — SharedSettings (Arc<Mutex<…>>), Shutdown, границы значений
src/keys.rs     — VK-коды ↔ имена (тестируется на любой ОС)
src/tray.rs     — иконка + меню трея (tray-icon/muda)
src/winapi.rs   — единственное место unsafe: GetAsyncKeyState/SendInput/timeBeginPeriod/MessageBoxW
```

## Ограничения и примечания

- **UIPI**: клики не доходят до окон, запущенных от администратора, если автокликер
  запущен без прав администратора. Запустите автокликер от администратора при необходимости.
- Кнопка активации **ЛКМ**: удерживайте её вне окна автокликера, иначе клики попадают и по GUI.
- **F12** зарезервирован под аварийный выход (GUI предупредит при выборе; на время
  режима «Слушать» watcher приостанавливается, чтобы F12 можно было выбрать осознанно).
- Антивирусы/SmartScreen могут предупреждать о неподписанном автокликере — это ожидаемо
  для инструментов автоматизации ввода.
- Инструмент предназначен для автоматизации собственных действий. В онлайн-играх
  использование автокликеров может нарушать условия сервиса/античит — вы отвечаете сами.

- [ ] Старт/Стоп; смена кнопки на лету; предупреждения для F12 и ЛКМ.
- [ ] Крестик → трей; ЛКМ по иконке / «Показать окно» → окно; «Выход» → процесс завершён, иконка исчезла.

- [ ] Клики доходят до Блокнота/браузера; один `.exe` без консоли и внешних файлов; иконка в Проводнике.
