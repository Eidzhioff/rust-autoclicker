# Техническое задание: Rust Autoclicker с GUI и System Tray

**Роль:** Ты — Senior Rust Developer. Твоя задача — написать полноценное desktop-приложение (автокликер) на языке Rust, заменив текущий прототип на Python.

## 1. Стек технологий
- **Язык:** Rust
- **GUI (Минималистичный):** `egui` + `eframe` (или `slint`, на твое усмотрение, но интерфейс должен быть легким и нативным).
- **System Tray:** Крейт `tray-icon` (или встроенные возможности Tauri, если выберешь Tauri).
- **Работа с Windows API (Ввод/Вывод):** Крейт `windows` (для `GetAsyncKeyState`, `SendInput` / `mouse_event`).
- **Потоки:** `std::thread` и `std::sync::mpsc` / `Arc<Mutex<T>>` для связи GUI и потока кликера.

## 2. Функциональные требования

### 2.1. Интерфейс (GUI)
Небольшое окно с минималистичным дизайном:
1. **Выбор кнопки активации:**
   - Выпадающий список (ComboBox) или поле ввода.
   - Должно поддерживать выбор *любой* клавиши клавиатуры и кнопок мыши (ЛКМ, ПКМ, СКМ, XButton1, XButton2, F1-F12, Space, Enter и т.д.).
   - *Реализация:* Предложить пользователю нажать кнопку "Слушать", после чего приложение перехватывает следующее нажатие (через хуки или опрос) и записывает соответствующий Virtual-Key (VK) код.
2. **Настройка задержки (Delay):**
   - Числовое поле ввода (или слайдер) для задержки в миллисекундах.
   - Значение по умолчанию: `40`.
   - Минимальное значение: `1`.
3. **Кнопка управления:**
   - "Старт / Стоп" (или автоматический старт при сворачивании в трей).

### 2.2. Поведение окна и System Tray
- **Сворачивание:** При нажатии на кнопку "Свернуть" (или "Закрыть" в настройках) окно скрывается, приложение продолжает работать в фоне.
- **System Tray:**
  - В трее появляется иконка.
  - При клике по иконке правой кнопкой мыши открывается контекстное меню:
    - `Показать окно` (разворачивает GUI).
    - `Выход` (полностью завершает процесс).
- **Закрытие:** Крестик на окне по умолчанию должен сворачивать в трей, а не закрывать приложение (если пользователь не нажал "Выход" в трее).

### 2.3. Логика автокликера (Фоновый поток)
- Отдельный `daemon` поток, который работает, пока приложение запущено.
- В цикле опрашивает состояние выбранной кнопки через `GetAsyncKeyState(VK_CODE)`.
- Если кнопка зажата (старший бит `0x8000`), вызывает симуляцию клика ЛКМ через `SendInput` (или `mouse_event`).
- Соблюдает задержку (`thread::sleep(Duration::from_millis(delay))`), которая может динамически меняться из GUI через `Arc<Mutex<Settings>>`.
- **Экстренный выход:** Зарегистрировать глобальный хоткей (например, `F12` или `Ctrl+Q`), который принудительно останавливает поток и закрывает приложение, если GUI зависнет.

## 3. Структура проекта
Предоставь код, разделенный на логические модули:
- `Cargo.toml` (со всеми необходимыми зависимостями и фичами, например `windows` с фичами `Win32_UI_Input_KeyboardAndMouse`, `Win32_UI_WindowsAndMessaging`).
- `src/main.rs` (Точка входа, инициализация GUI и Tray).
- `src/clicker.rs` (Логика потока, опрос клавиш, симуляция мыши).
- `src/settings.rs` (Структура настроек, разделяемая между потоками).
- `src/tray.rs` (Настройка иконки и меню трея).

## 4. Требования к коду
- Код должен быть безопасным (минимизировать `unsafe`, инкапсулировать его в отдельные функции-обертки для Win32 API).
- Обработать ошибки gracefully (не использовать `.unwrap()` в продакшн-коде, использовать `Result` и `Option`, показывать ошибки в GUI или логах).
- Приложение должно компилироваться в один `.exe` файл (добавить инструкции по сборке через `cargo build --release` и, при необходимости, скрытию консоли через `windows_subsystem = "windows"` в `Cargo.toml`).

**Начни с генерации `Cargo.toml` и структуры файлов, затем напиши полный код для каждого модуля.**
